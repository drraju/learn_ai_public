# Study sequence

Follow this route from the repository root. Each module has a concept guide, a guided exercise and an independent challenge. Use the reference in the guided demonstration, then complete the independent challenge with your own change and explanation. Passing reference tests does not complete your assessment.

| Step | Study | Practice and checkpoint | Continue when you can… |
|---|---|---|---|
| 1 | [M00 software foundations](modules/m00-software/README.md) | Complete the [catalogue lab](modules/m00-software/labs/README.md). | Explain a Python/HTTP/SQLite change, run a normal and a failure test, and describe rollback. |
| 2 | [M01 AI foundations](modules/m01-foundations/README.md) | Run the [three offline demonstrations](modules/m01-foundations/labs/README.md). | Distinguish training from inference and identify where the token, vector and attention analogies fail. |
| 3 | [M02 interfaces](modules/m02-interfaces/README.md) → [M03 context](modules/m03-context/README.md) | Build [P1](projects/p01_llm_app/README.md): first validate the fixture contract, then compare context or prompt choices on fixed cases. | Reject malformed output and explain what output checks cannot prove. Keep a case-by-case comparison; the reference does not implement a full prompt benchmark. |
| 4 | [M04 ingestion](modules/m04-ingestion/README.md) → [M05 retrieval](modules/m05-retrieval/README.md) | Build [P2](projects/p02_rag/README.md): version sources before scoring retrieval and checking citations. | Show update, deletion, tenant isolation, abstention and Recall@k with a denominator. The reference answer is extractive. |
| 5 | [M06 tools](modules/m06-tools/README.md) → [M07 state](modules/m07-state/README.md) | Build [P3](projects/p03_tool_agent/README.md): read-only loop first, exact-action simulated approval second. | Deny an unknown tool and stale or mismatched approval; show termination and idempotency. Approval is in memory in the reference. |
| 6 | [M08 MCP](modules/m08-mcp/README.md) | Build [P4](projects/p04_mcp/README.md) when the optional MCP SDK is available; otherwise study host policy and the denial path, and record the exchange as blocked. | Explain host/client/server trust and show an allowed and a denied exchange when using the SDK. MCP runtime work is an optional integration branch. |
| 7 | [M09 orchestration](modules/m09-orchestration/README.md) | Build [P5](projects/p05_multi_agent/README.md): compare a single-role baseline with a two-role workflow on the same cases. | Explain disagreement and decide whether the extra role earns its cost. M08 is not required for this comparison. |
| 8 | [M10 evaluation](modules/m10-evaluation/README.md) | Revisit P1–P5 with frozen normal, failure and attack cases; start [P6 evaluation](projects/p06_capstone/README.md). | Report denominators, policy failures and limits without treating passing reference tests as learner competence. |
| 9 | [M11 deployment](modules/m11-deployment/README.md) → [M12 capstone](modules/m12-capstone/README.md) | Run P6 locally, follow its runbook, and prepare the portfolio defense. | Demonstrate a case and failure, explain recovery, and name the production gaps. |

At every step, use [the assessment framework](ASSESSMENT_FRAMEWORK.md) to record the command, input, expected and observed result, one negative case, a design decision and what remains unverified. Use [learning paths](LEARNING_PATHS.md) for diagnostic skips. A skipped lesson still requires its project evidence. Live providers and model downloads are optional and need explicit opt-in, version, hardware and cost notes. The published course is a draft; [Stage 5 QA](QA_REPORT.md) remains open.
