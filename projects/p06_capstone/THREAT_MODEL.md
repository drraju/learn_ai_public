# Local capstone threat model

Assets: synthetic runbooks, tenant scope, action authority, demo token and request trace. Trust boundaries: HTTP client to service, service to fixtures, proposed tool to application policy. The service binds to loopback and requires a demo bearer token for investigation. This token is shared process configuration, not real user identity. The demo token is bound to the fixed `demo` tenant; a different caller-supplied tenant is denied. This is still not real user authentication or multi-tenant authorization. A production service would require authenticated identity, tenant authorization, durable approval, rate limits, audit retention, TLS at an appropriate boundary and operational monitoring. Do not expose this reference service publicly. Model or retrieved text must never grant tool permission.
